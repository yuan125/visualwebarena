# MolmoWebMix Dataset Processing

The MolmoWebMix dataset (`molmoweb_ground_qa_train_10k.jsonl`, `molmoweb_ground_qa_eval_1k.jsonl`) is constructed by merging two branches of data derived from the `allenai/MolmoWeb-SyntheticGround` HuggingFace dataset. **For the grounding branch**, the script `sample_and_split_ground.py` streams the `gpt` config / `train` split, shuffles with a buffer of 5,000 (seed 42), and collects 11,000 examples — one randomly chosen grounding message per image. Each image is skipped if it has no messages or fails PIL conversion; otherwise the PIL image is converted to RGB, saved as JPEG (quality 85), and base64-encoded inline. The prompt is converted into Fireworks VLM SFT format: a **system** message instructing a web browsing agent to output JSON with `thought`, `action`, and `coordinate` (percentage 0–100), a **user** message containing the base64 `image_url` plus the question text, and an **assistant** message with the JSON-serialized answer (`thought`, `action` name, `[x, y]` coordinate). The 11,000 examples are then split into 10,000 train (`molmoweb_ground_train_10k.jsonl`) and 1,000 eval (`molmoweb_ground_eval_1k.jsonl`). **For the QA branch**, `molmoweb_qa_train_10k.jsonl` (10,000 lines) and `molmoweb_qa_eval_1k.jsonl` (1,000 lines) are produced analogously from the same HuggingFace source but converted into a multi-turn QA format: a system prompt ("You are a web browsing assistant. Given a screenshot of a webpage, answer questions about its content, layout, and interactive elements."), the first user turn carrying the base64 image plus a question, and subsequent user/assistant turns with text-only follow-up QA pairs about the same screenshot. **The merge step** (`combine_datasets.py`) concatenates the ground and QA JSONL files for each split and shuffles with `random.Random(42)`, producing `molmoweb_ground_qa_train_10k.jsonl` (~20,000 lines: 10k ground + 10k QA) and `molmoweb_ground_qa_eval_1k.jsonl` (~2,000 lines: 1k ground + 1k QA). **To mix MolmoWebMix with VWA examples**, the pipeline first downsamples the combined files to 10% via `downsample_datasets.py` (`random.Random(42).sample`, yielding `molmoweb_ground_qa_train_downsample_1k.jsonl` ~2,000 lines and `molmoweb_ground_qa_eval_downsample_100.jsonl` ~200 lines), then `combine_sft_molmoweb.py` concatenates each downsampled MolmoWebMix file with the corresponding VWA SFT file (`sft_image_resized.jsonl` for train, `sft_image_resized_eval.jsonl` for eval), shuffles with seed 42, and writes the final mixed datasets `sft_image_resized_with_molmoweb_train.jsonl` and `sft_image_resized_with_molmoweb_eval.jsonl`, which are then uploaded to Fireworks for fine-tuning.
